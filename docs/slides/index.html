المشكلة وفكرة DealGuard

الإعلانات تخفي الاستثناءات والحد الأعلى للخصم والحد الأدنى للإنفاق وتواريخ الانتهاء، فلا يرى المتسوق أو موظف الدعم السعر الحقيقي بسهولة. وقد يخترع روبوت محادثة عادي سياسات أو يخطئ في حساب المال.

ما يميّز DealGuard

مبني على المصدر

رفض آمن

كوبون مجهول أو مفقود يعطي REFUSED، بلا سياسة مخترعة وبلا خصم.

حساب حتمي للمال

الأهلية والأسعار تُحسب في Python، لا بنموذج ذكاء اصطناعي.

شفافية

الواجهة تعرض الدليل وفحوص القواعد وخطوات الحساب، وهل الشرح مولَّد بقالب أم بنموذج.

Gemini (اختياري) يعيد صياغة الحقائق المتحقق منها فقط، ويُرفض ناتجه إذا أضاف رقمًا أو أغفل معرّف المصدر.

التقنيات ودورها الفعلي

منفَّذ = يعمل اليوم. اختياري = في الكود لكنه يحتاج مفتاح API من المستخدم. مستقبلي = غير مبني بعد.

التحقق من المدخلات

السعر موجب وحتى مليون ريال؛ الكوبون من 3 إلى 20 حرفًا؛ الادّعاء حتى 300 حرف

الاسترجاع

تشابه جيب التمام: أعلى 3 نتائج بحد أدنى 0.05

الرفض الآمن

كوبون مجهول يعطي REFUSED، بلا خصم ولا سياسة مخترعة

1. User input
2. Validation
3. TF-IDF retrieval (top 3, min score 0.05)
4. Rule verification (expiry, category, min spend)
5. Discount calculation (percent+cap | flat | free shipping)
6. Claim check ("%" / "SAR" vs real discount)
7. Explanation (template | Gemini + grounding guard)

الشرح قالب افتراضيًا؛ عند ضبط GEMINI_API_KEY يعيد Gemini الصياغة ويقبلها الحارس أو يرفضها.
